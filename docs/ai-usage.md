## 2. 서비스 내 AI 활용 범위
아래 기능들에 AI 가 사용된다.

- **개인정보 유출 안내문 분석:** 유출 안내문에서 기업명, 서비스명, 유출된 개인정보 항목, 예상 가능한 2차 피해 유형과 판단 근거를 추출한다. 이미지가 입력된 경우 Tesseract.js를 이용해 텍스트를 인식하며, 원본 이미지와 흑백·대비 보정 이미지의 인식 결과 중 신뢰도가 높은 결과를 분석에 사용한다.
- **관련 사고 정보 검색 및 설명 생성:** AI가 추출한 정보들로 ‘기업명+개인정보 유출’ 검색어를 구성한 후 네이버 뉴스 검색 API로 최신 관련 기사 최대 5건을 조회한다. 검색된 기사에 포함된 정보는 최종 설명을 생성하기 위한 참고 자료로만 활용된다.
- **의심 문자 분석:** 의심 문자에서 링크 클릭, 본인인증, 앱 설치, 금융정보 입력 요구와 긴급성·기관 사칭 표현 등을 분석한다. 이를 바탕으로 위험등급, 스미싱 의심 여부, 사칭 유형 및 문자 내용에 근거한 판단 이유를 제공한다.
- **결과 활용 문서 생성:** 분석된 기업명, 유출 항목과 위험 유형을 바탕으로 외부에 전달 가능한 쉬운 안내문을 생성한다. 기관 상담·신고용 요약문은 서버가 만든 사실 중심의 기본 템플릿을 AI가 자연스럽게 정리하며 제목과 누락 항목은 서버 값을 유지하고 유효하지 않은 결과는 기본 템플릿으로 대체한다.

## 3. AI 활용 고도화 및 안전성 확보

- **사용자 개인정보 보호:** 외부 AI 모델 호출 전, 입력된 정보에 포함된 개인정보를 서버에서 비식별 표기로 마스킹한다. 요약문 생성 시에는 개인정보를 임시 내부 토큰으로 치환하고, AI가 이를 수정하거나 삭제하지 않도록 제한한 뒤 생성 결과에서 원래 값으로 복원한다.
- **공통 프롬프트 제한:** AI가 사용자 입력에 없는 개인정보·요구사항·피해 사실을 임의로 추가, 가정 하지 않도록 제한한다. 검색 API 를 이용해 수집한 검색 기사는 참고 자료로만 사용하며, 다른 기업·피해자·유출 항목을 현재 사고와 혼합하거나 사용자의 실제 피해 증거로 간주하지 않는다. 위험 가능성과 실제 피해를 구분하고 확정적이거나 불안을 과도하게 유발하는 표현도 제한한다.
- **규칙 기반 결과 보정 및 출력 검증:** 유출 항목을 서버 기준에 적용해 최종 위험점수와 위험등급을 계산하고, 사전 정의된 규칙에서 관련 체크리스트만 선택한다. AI 응답은 JSON으로 제한하며   누락값·자료형을 검사하고 공백·빈 값·중복 항목을 정리한다. 가족 공유문과 신고 요약문의 유효하지 않은 부분은 서버에서 정의한 기본값으로 대체된다.
- **입력 및 장애 대응:** 유출 안내문은 30,000자, 의심 문자는 5,000자, 신고 요약문은 전체 문자열 기준 20,000자로 제한한다. 네이버 뉴스 검색에는 8초, AI 분석에는 30초의 제한 시간을 적용하고 초과 시 `AbortController`로 요청을 중단한다. 검색 실패 시 검색 결과 없이 AI 분석을 이어가고 신고 요약문 생성 실패 시 서버의 기본 템플릿을 반환한다. 내부 API 오류와 상세 내용은 사용자에게 노출하지 않고 재시도를 안내한다.

## 4. AI 생성 코드의 검증·수정 방식

AI 코딩 도구를 기능 설계, TypeScript·React 코드 및 API 연동 코드의 초안 작성, 오류 분석, 리팩터링, UI 문구와 문서 작성에 활용했다. AI에 의해 생성된 코드는 그대로 반영하지 않고 프로젝트 구조와 동작 조건에 맞게 다음과 같이 검토·수정했다.

1. 코드의 동작과 적용 범위를 확인하고 기존 타입 정의·API 응답 형식·프로젝트 구조와의 일치 여부 검토
2. 외부 API 키의 클라이언트·GitHub 노출 여부와 TypeScript·Next.js 빌드 오류 확인
3. 유출 안내문과 의심 문자 예시를 입력해 결과를 비교하고, 입력에 없는 유출 항목이나 피해 사실의 추가 여부 확인
4. 빈 입력·긴 입력·검색 실패·AI 응답 지연·잘못된 JSON 등의 예외 상황과 PC·모바일의 결과 표시·체크리스트·PDF 저장·분석 이력 기능 검토
5. 외부 피드백과 팀원 QA를 반영하여 프롬프트·위험도 기준·개인정보 마스킹·오류 처리·UI를 반복 수정
