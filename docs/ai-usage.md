## 1. AI 활용 개요

LeakCare 프로젝트는 개인정보 유출 안내문을 받은 사용자가 복잡한 유출문을 직접 해석하지 않고도 유출된 정보와 예상되는 2차 피해를 파악하고, 우선순위에 따라 대응할 수 있도록 돕는 AI 활용 웹서비스이다.

본 서비스에서 AI  도구들은 다음과 같이 사용된다.

- 생성형 AI: 비정형 안내문 해석, 핵심 정보 추출, 의심 문자 분석, 설명문 및 신고용 요약문 생성
- 검색 API: AI가 추출한 기업명과 관련된 개인정보 유출 기사 조회로 유출 사실 검증
- 개인정보 보호 로직: 외부 AI API 호출 전 개인정보 마스킹
- 예외 처리 로직: AI 또는 검색 API 장애 시 서비스 중단 최소화

본 서비스에서 AI 는 다음과 같은 흐름으로 사용된다.

사용자 입력→텍스트 추출 및 개인정보 마스킹→비정형 내용 분석→관련 뉴스 검색으로 정보 확인→AI 설명 생성→서버의 출력 검증, 정규화→규칙 기반 위험도 및 대응 조치 결정→사용자 맞춤형 결과제공

## 3. 서비스 내 AI 활용 범위

### 3.1 개인정보 유출 안내문 유출 정보 추출

사용자가 입력한 개인정보 유출문 또는 이미지를 기반으로 작동한다. 이미지의 경우 Tesseract.js를 통해 텍스트를 추출하며, 원본 이미지와 흑백·대비 보정 이미지를 각각 인식한 후 신뢰도가 더 높은 결과를 사용한다. 

추출된 텍스트는 마스킹 과정을 거치고 Gemini API에 전달되어 다음 정보를 JSON 구조로 변환한다.

- 유출 사고와 관련된 기업명
- 서비스명
- 안내문에 명시된 개인정보 유출 항목
- 예상 가능한 2차 피해 및 위험 유형
- 판단 근거

Gemini 호출 시 temperature 를 0.2로 낮게 설정하고, 응답 형식을 JSON으로 제한해 같은 입력에 대한 결과 변동을 줄이고 서버에서 안정적으로 파싱되도록 한다.

또한 프롬프트에 다음 제한을 적용해 AI 임의의 판단을 막는다.

- 안내문에 명시되지 않은 개인정보를 임의로 추가하지 않는다.
- 카드번호와 계좌번호, 비밀번호 등 민감정보가 실제로 유출되었다고 명시된 경우에만 해당 항목을 포함한다.
- 결제정보가 유출되었다는 이유만으로 카드번호나 계좌번호도 유출되었다고 추정하지 않는다.
- 피해가 발생했다고 명시되지 않았다면 실제 피해가 발생한 것으로 단정하지 않는다.
- 기업명을 확인할 수 없으면 임의로 추정하지 않고 ‘알 수 없음’ 으로 반환한다.
- IMSI, IMEI, 유심 인증키 등 새로운 개인정보 항목을 일반적인 계정 정보로 임의 변환하지 않고 원문의 의미를 유지한다.

### 3.2 관련 사고 정보 검색 및 분석 보조

Gemini가 추출한 정보를 기반으로 기업명 + 개인정보 유출 형식의 검색어를 구성되면 네이버 뉴스 검색 API가 최신 관련 기사 최대 5건을 조회한다.

검색 결과의 제목, 요약, 원문 URL을 Gemini의 최종 설명 생성 과정에 참고 자료로 제공한다. 다만 검색 결과를 사용자의 실제 피해 사실로 오인하지 않도록 다음과 같은 프롬프트로 제한한다.

- 검색 기사는 일반적인 사고 사례와 사칭 수법을 설명하는 참고 자료로만 활용한다.
- 검색 기사에 등장한 다른 기업, 피해자 또는 유출 항목을 현재 사용자의 사고에 혼합하지 않는다.
- 검색 결과가 없거나 현재 사고와 직접 관련이 없다면 억지로 연관성을 만들지 않는다.
- 검색 결과만으로 실제 피해 발생 여부를 단정하지 않는다.
- 현재 안내문에서 확인된 사실과 검색 자료를 명확히 구분한다.

네이버 검색 API가 실패하거나 8초 안에 응답하지 않더라도 검색 결과를 빈 배열로 처리해 안내문 자체에 대한 AI 분석은 계속 수행되도록 구현했다.

### 3.3 맞춤형 대응 체크리스트 제공

Gemini가 스스로 대응 방법을 생성하면 사고와 무관하거나, 과도한 조치가 포함될 수 있으므로 최종 대응 체크리스트는 유출 항목별로 사전에 정의한 규칙을 사용한다.

Gemini가 유출된 개인정보 항목을 추출해 제공하면 서버는 사전에 정의된 대응 규칙 중 해당 유출 항목과 연결된 조치만 선택하여 맞춤형 체크리스트를 구성한다.

### 3.4 의심 문자 분석

스미싱, 피싱 등 개인정보 유출의 우려가 있는 의심 문자 분석 기능을 제공한다.

사용자가 입력한 문자 내용은 개인정보 마스킹을 거친 후 미리 작성된 분석 프롬프트와 결합하여 Gemini API에 전달된다.

프롬프트는 Gemini의 역할을 스미싱, 피싱 의심 문자를 분석하는 보안 도우미로 제한하며 다음 요소를 중심으로 판단하도록 작성했다.

- 문자에 포함된 링크의 클릭 유도
- 본인인증 요구
- 앱 설치 요구
- 계좌번호·카드번호·비밀번호 등의 입력 요구
- 보상금, 환불, 배송 실패, 계정 정지 등 긴급성을 강조하는 표현
- 기업이나 공공기관을 사칭하는 표현

Gemini의 응답은 자유 형식의 문장이 아닌 JSON으로 제한되며 다음 정보를 반환한다.

- 위험등급: 낮음, 보통, 높음
- 스미싱 의심 여부
- 스미싱, 본인인증 사칭, 택배 사칭, 환불 사칭 등의 위험 유형
- 문자 내용에 근거한 판단 이유

또한 AI가 입력문에 없는 내용을 임의로 생성하지 않도록 프롬프트에 다음 제한 규칙을 적용한다.

- 문자에 실제로 포함된 내용만 판단 근거로 사용한다.
- 입력되지 않은 링크나 요구사항을 만들어내지 않는다.
- 피해 발생이 명시되지 않았다면 실제 피해가 이미 발생한 것으로 단정하지 않는다.
- 위험 가능성과 실제 피해 사실을 구분하여 설명한다.

### 3.5 가족 공유문 및 신고·상담용 요약문 생성

사용자가 분석 결과를 실제 대응에 활용할 수 있도록 다음 문서를 생성한다.

- 가족이나 지인에게 전달할 수 있는 쉬운 안내문
- 기관 상담 또는 신고에 활용할 수 있는 사실 중심 요약문

Gemini는 사용자가 입력한 내용과 서버가 먼저 생성한 기본 템플릿 안에서 문장만 자연스럽게 정리하며, 이 과정에서 내용을 임의로 추가하거나 수정할 수 없도록 제한한다.

제목과 누락 항목 판단은 AI에 맡기지 않고 서버에서 생성한 값을 유지한다. AI 응답에서 일부 항목이 빠지거나 올바르지 않으면 해당 부분은 서버의 기본 템플릿으로 대체한다.

## 4. AI 활용 고도화 및 안전성 확보

### 4.1 개인정보 마스킹

사용자가 입력한 유출 안내문에는 이름, 전화번호, 이메일, 주소, 주민등록번호, 카드번호 및 계좌번호 등 실제 개인정보가 포함될 수 있기에 Gemini API 호출 전 서버에서 개인정보를 마스킹한다.

마스킹 대상은 다음과 같다.

- 주민등록번호
- 카드번호
- 이메일
- 전화번호
- 계좌번호
- 주소
- 이름

개인정보를 [전화번호], [이메일], [주소]와 같은 비식별 표기로 치환한 텍스트로 Gemini에 전달한다.

신고 요약문 생성에서는 각각의 개인정보를 임시 내부 토큰으로 변환한 뒤 Gemini에 전달한다. Gemini에는 토큰을 수정하거나 삭제하지 말라는 규칙을 적용하고 생성 결과를 받은 후 서버에서 원래 값으로 복원한다. 이에 따라 Gemini는 실제 개인정보를 알지 못하지만, 사용자에게 반환되는 요약문에서는 문맥과 정보 구분을 유지할 수 있다.

API 키는 코드나 GitHub 저장소에 직접 포함하지 않고 .env. `.env.local` 또는 배포 환경변수로 관리한다.

### 4.2 AI 혼란 방지

AI가 확인되지 않은 내용을 제공하는 문제에 대비해 다음 조치를 적용한다.

1. 출력 형식을 JSON으로 제한한다.
2. 입력문에 없는 개인정보와 피해 사실을 추가하지 못하도록 프롬프트에 명시한다.
3. 검색 결과를 현재 사용자의 유출 사실이나 피해 증거로 사용하지 못하도록 제한한다.
4. 카드번호가 확인되지 않으면 카드 정지나 금융 피해를 권고하지 않도록 제한한다.
5. 비밀번호가 확인되지 않으면 비밀번호 유출 또는 계정 탈취를 단정하지 않도록 제한한다.
6. 피해 가능성은 “악용될 수 있음”, “주의가 필요함”과 같이 표현하고 피해 발생을 확정적으로 표현하지 않도록 한다.
7. 사용자의 불안을 과도하게 유발하는 문장을 제한한다.
8. Gemini가 위험등급을 변경하지 못하도록 최종 위험등급을 규칙 기반 결과로 덮어쓴다.
9. Gemini가 새로운 위험 유형을 임의로 추가한 경우 기존 분석에서 확인된 위험 유형만 남긴다.

### 4.3 AI 출력 검증 및 정규화

Gemini의 응답은 서버에서 다음 절차로 검증된다.

- Markdown 코드 블록을 제거한 후 JSON으로 파싱
- JSON 이외의 문장이 포함된 경우 객체 부분만 추출
- 잘못되거나 누락된 값에 기본값 적용
- 위험등급을 낮음, 보통, 높음 중 하나로 제한
- 배열이 아닌 값 제거
- 문자열 공백 제거
- 빈 값 제거
- 중복 유출 항목 및 위험 유형 제거
- 유출 항목의 유사 표현을 내부 표준 명칭으로 정규화
- 확인되지 않은 위험 유형을 허용 목록 기반으로 제거
- AI가 작성하지 못한 설명문은 서버의 기본 문장으로 대체

### 4.4 장애 및 과도한 입력 대응

외부 서비스 장애가 전체 서비스 장애로 이어지지 않도록 다음 처리를 적용한다.

- 유출 안내문 입력은 최대 30,000자로 제한
- 의심 문자 입력은 최대 5,000자로 제한
- 신고 요약문 입력은 전체 문자열 기준 최대 20,000자로 제한
- 네이버 뉴스 검색은 8초 제한
- Gemini 분석은 30초 제한
- 제한 시간이 지나면 `AbortController`로 요청 중단
- 네이버 검색 실패 시 검색 결과 없이 AI 분석 계속 수행
- 신고 요약문 AI 생성 실패 시 규칙 기반 템플릿 반환
- 내부 API 오류 및 상세 오류 내용은 사용자에게 그대로 노출하지 않고 재시도 안내 메시지 제공

## 5. AI 생성 코드의 검증·수정 방식

개발 과정에서 AI 코딩 도구는 기능 구현 아이디어, TypeScript 및 React 코드 초안, API 연동 코드, 오류 원인 분석, 리팩터링, UI 문구와 문서 작성을 보조하는 용도로 활용된다.

AI가 생성하거나 제안한 코드는 그대로 반영하지 않고 다음 절차를 통해 검토·수정한다.

1. AI 제안 코드의 동작과 적용 범위 확인
2. 기존 타입 정의, API 응답 형식 및 프로젝트 디렉터리 구조와 일치하는지 검토
3. 외부 API 키가 클라이언트 또는 GitHub 저장소에 노출되지 않는지 확인
4. TypeScript 오류와 Next.js 빌드 오류 확인
5. 개인정보 유출 안내문과 의심 문자 예시를 직접 입력해 결과 비교
6. AI가 입력문에 없는 유출 항목이나 피해 사실을 추가하는지 확인
7. 정상 입력 뿐 아니라 빈 입력, 긴 입력, 검색 실패, AI 응답 지연, 잘못된 JSON 등 예외 상황 검토
8. PC와 모바일 환경에서 입력, 결과 표시, 체크리스트, PDF 저장, 분석 이력 기능 확인
9. 외부 피드백과 팀원 QA 결과를 반영해 프롬프트, 위험도 기준, 개인정보 마스킹, 오류 처리 및 UI 반복 수정

검증 과정에서 발견한 주요 문제와 수정 내용은 다음과 같다.

| 발견한 문제 | 검증 및 수정 내용 |
| --- | --- |
| AI가 확인되지 않은 유출 정보나 피해 사실을 추가할 수 있음 | 입력문에 명시된 사실만 사용하도록 프롬프트를 강화하고 위험 유형 허용 목록 필터링 적용 |
| 같은 입력에서도 AI 위험등급이 달라질 수 있음 | 최종 위험점수와 위험등급을 자체 규칙 기반 계산 로직으로 분리 |
| 유출 항목의 표현 차이로 위험도 계산이 누락됨 | 전화번호, 계정정보, IMSI, IMEI, 유심 인증키, CI, DI 등의 별칭 정규화 추가 |
| 외부 AI에 실제 개인정보가 전달될 가능성이 있음 | Gemini 호출 전 개인정보 마스킹 및 신고 요약문의 토큰 치환·복원 적용 |
| 검색 API 장애가 전체 분석 실패로 이어짐 | 검색 실패 시 빈 검색 결과로 분석을 계속하는 예외 처리 추가 |
| AI 응답이 오래 걸릴 경우 요청이 계속 대기함 | 검색 8초, Gemini 30초 타임아웃 및 요청 중단 처리 추가 |
| AI 응답에 누락된 JSON 필드가 존재함 | 타입 검사, 기본값 및 서버 템플릿 대체 처리 추가 |
| AI가 과도하거나 무관한 대응책을 제시할 수 있음 | 체크리스트를 AI 자유 생성 방식이 아닌 유출 항목별 규칙 기반 방식으로 변경 |
| 신고 요약문 생성 실패 시 기능을 이용할 수 없음 | Gemini 없이도 반환 가능한 기본 신고·상담용 템플릿 구현 |
| 통신 관련 새로운 유출 항목이 기존 항목으로 잘못 분류됨 | IMSI, IMEI, CI, DI, 유심 인증정보를 별도 위험 항목으로 확장 |

개인정보 보호, 위험도 산정 및 사용자 대응 조치와 같이 결과의 신뢰성이 중요한 부분은 AI에 의존하지 않고 명시적인 규칙과 예외 처리 코드를 추가해 보완한다.
